## 平台支持

核心功能（对话文件夹、交接日志、删除对话、右键菜单、备份、体检）在 **Windows / macOS / Linux** 都能用。
但有几项是 **Windows 专用**，在别的系统上会**直接隐藏**，不会留一个点了没反应的按钮：

| 功能 | Windows | macOS / Linux |
| --- | --- | --- |
| 每个对话一个文件夹、交接日志 | ✅ | ✅ |
| 删除对话（可恢复）、批量删除 | ✅ | ✅ |
| 文件右键菜单：打开 / 复制路径 / 另存为 / 重命名 / 移到回收站 | ✅ | ✅ |
| 文件右键菜单：**解压到此处** | ✅ 用系统 `tar.exe` | ❌ 隐藏 |
| 网址菜单：**用其它浏览器打开** | ✅ 读 `StartMenuInternet` 注册表 | ❌ 隐藏（只留「在默认浏览器打开」） |
| 文件右键菜单：**在终端中打开** | ✅ | ❌ 隐藏 |

如果你在非 Windows 上发现某个菜单项**显示了但点了没反应**，那是 bug，请开 issue。

## 它解决什么问题

DSH 原生把「对话」放在侧边栏，但：

- 对话一多，**找不到某个对话对应的文件** —— 它没有「每个对话一个目录」的概念。
- 删对话是**不可逆**的 —— 手滑一次，记录就没了。
- 对话里的文件卡片只能点开，**不能右键**做「打开文件夹 / 复制路径 / 另存为」；
  而且不同文件想做不同的事（图片、代码、压缩包），没有分类型的入口。
- 对话里的**链接只能点开** —— 不能换浏览器打开、不能只复制 URL、不能复制成 Markdown 链接。
- 想让 agent 每次都遵守同一套安全基线，**没有统一入口** —— 只能每个工作区各写一份 `AGENTS.md`。

这个插件把这五件事一次做完，并且只有**一个 bundle、一个开关、一个设置页**。

### 1.7.4

**把「完全重启」改成诚实的「关闭窗口」——因为我发现它根本做不到。**

这一条我要说清楚：**1.7.0 ~ 1.7.3 的「完全重启」是错的**，三轮都没做对。
把每一次的失败原因记下来，免得以后又走回去：

| 尝试 | 结果 | 原因 |
| --- | --- | --- |
| `window.close()` | 只是隐藏到托盘 | 主进程 `window.on("close")` 里 `preventDefault()` 后调 `backgroundNotice.close(hide)` |
| `process.kill(SIGTERM)` | 弹「应用意外停止」 | Windows 上是强杀，退出码 1，主进程 `child.once("close")` 看到非 0 就 `fail()` |
| `process.exit(0)` | 一样弹 | 压住弹窗的 `stopping` 标志只有主进程自己能改 |
| 游离 powershell「杀进程+拉起」 | **DSH 纹丝不动** | 宿主活在 DSH 的 Windows Job Object 里（asar 有 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），`detached` 逃不出 Job：父进程一死，脚本被一起回收，**还没杀进程就已经死了** |

要让脚本活得比宿主久，只能用 `schtasks` / `wmic` / 服务这类**系统级手段**，
那超出了插件该碰的范围。

**所以现在的行为是**：菜单项叫「关闭窗口…」，点了走 `window.close()`
（唯一不弹崩溃框的路径），窗口隐藏到系统托盘，进程继续跑；
要真正结束 DSH，从托盘菜单选「退出」。文案和二次确认都如实这么写。

顺便修掉一个真实 bug：`restartQuit` 这个文案键在中文表里**重复定义了两次**。

自检 15 条不变，但「关闭窗口」那条断言现在会同时检查：
不许出现 `process.kill`/`process.exit`/`spawn('powershell.exe')`、
必须走 `window.close()`、**文案里不许承诺「自动重新打开」**。

### 1.7.3

**「完全重启」现在真的会重开，不再只是关掉让你自己再打开一次。**

1.7.1/1.7.2 那版用的是 `window.close()`。查了主进程源码才发现它被拦下来了：

```js
window.on("close", (event) => {
  if (quitting || ...) return;
  event.preventDefault();          // ← 不关
  backgroundNotice.close(hide);    // ← 只是 hide 到托盘
});
```

所以点完只是窗口消失、进程还在，得自己再打开。而 `process.kill` / `process.exit`
两条路都被堵死（强杀 → 崩溃弹窗；`exit(0)` 也一样，因为压住弹窗的 `stopping`
标志只有主进程自己能改）。

**现在的做法**：插件起一个游离的 powershell，由它完成整件事——

1. 等 800ms，让我们把回话交出去；
2. 按 exe 路径精确匹配，杀掉 DSH 进程树（不碰别的同名程序）；
3. **轮询等旧进程真的消失**（最多 15 秒）；
4. 用同一个 exe 重新启动。

第 3 步不能省。DSH 有单实例锁：旧进程还没退干净就启动，新实例会以为自己不是主人、
把锁交给旧实例然后自己退出 —— 表现为「点了重启，窗口一闪就没了」。

宿主这边仍然**不自己杀自己**：主进程一死，宿主收到 IPC `disconnect` 就 `stop()` 优雅收尾，会话日志不会被截断。

自检仍然是 15 条，但那条「完全重启」的断言换成了新设计的检查：
不许出现 `process.kill`/`process.exit`、必须起脚本、**必须带等待轮询**。

### 1.7.2

**修一个存在很久的 bug：写「交接日志.md」时并发撞车，会把 DSH 顶到崩溃弹窗。**

这个 bug 比「重启」功能老得多——10 月 27 日的崩溃日志里就是它，那时候还没有重启按钮。
弹窗是 DSH 自带的（宿主进程以退出码 1 结束时主进程就会弹），但**触发它的是这个错误**：

```
rename '...交接日志.md.tmp' -> '...交接日志.md': ENOENT
```

原因：写日志有四个并发入口（建目录时、`turn/end`、`end-seed`、手动命令），
而旧实现用**固定**的 `交接日志.md.tmp`：

```
A 写 tmp → B 也写同一个 tmp → A rename 成功（tmp 没了）→ B rename ENOENT
```

这条错误经 stderr 传给桌面版主进程，宿主一退出就弹「应用无法启动或已意外停止」。

**修法要两步，少一步都不行**（这是压测出来的）：

| 写法 | 并发 8 × 20 轮的失败次数 |
| --- | --- |
| ① 固定 tmp 名（原来的） | 120 次 `ENOENT` |
| ② 只把 tmp 名改唯一 | 仍有 91 次 `EPERM` |
| ③ 唯一 tmp 名 + 按会话串行化 | **0 次** |

② 会失败是因为 Windows 上多个 `rename` 并发覆盖同一目标会冲突（`EPERM`）。
所以现在两件事都做：tmp 名带 pid+时间戳+随机串，并且同一会话的写入排成一队（`logWriteQueue`），后触发的看到的是前一次的内容，保证自洽。

新增 `test/log-race.test.mjs`：真跑三组对照压测，并直接读源码确认插件用的是第 ③ 种。
自检 13 条 → **15 条**。

### 1.7.1

**修 1.7.0 的两个毛病：重启按钮会压在「应用」上，完全重启会弹崩溃框。**

两个都是我自己上一版留下的，原因都不难说清。

**① 按钮和原生菜单重合。** 原来的实现只在组件挂载时量一次原生菜单栏的位置，
而那一刻它往往还没被预加载脚本挂上（菜单栏在 `DOMContentLoaded` 之后才创建的），
于是退回到固定值 `left: 48px` —— 正好压在「应用」上。等菜单栏出现时没有 resize 事件，
错位就一直留着。**放大窗口会好**，因为那会触发 resize 重新测量。

现在三重保障：挂载后连续 8 次重量（覆盖「菜单栏稍后出现」）、
`MutationObserver` 盯着 body（菜单栏一挂上就重量）、resize + ResizeObserver（语言切换），
**并且量不到就不渲染**——宁可晚 100ms 出现，也不猜一个位置压在原生菜单上。

**② 完全重启弹「应用无法启动或已意外停止」。** 原来用 `process.kill(SIGTERM)` 退出，
而 Windows 上那等于 `TerminateProcess`，退出码是 **1**。桌面版主进程在
`child.once("close")` 里看到非 0 就调 `fail()`，弹崩溃框。

换成 `process.exit(0)` 也不行：那个 `fail()` 里还有一道
`if (!this.failureReported && !this.stopping)`，只有主进程自己发起 `stop()` 才压得住，
而 `stopping` 插件改不到。

正确做法是**关窗口**——那正是用户点右上角 ✕ 走的链路：
`window-all-closed → app.quit() → before-quit → finishQuit → backend.close() → host.stop()`，
全程无弹窗。所以现在宿主只回报「能不能靠关窗口退出」，真正的动作在客户端 `window.close()`。

自检 11 条 → **13 条**，新增两条正好分别钉住这两个坑。

### 1.7.0

**标题栏多了「↻ 重启」：软重启重载插件与界面，硬重启才退出整个 DSH。**

改插件代码之后要重启 DSH 才能看到效果，这件事一直很别扭。现在窗口左上角
「应用 编辑 视图」那一行右边多了一个按钮：

| 菜单项 | 做什么 | 会不会断会话 |
| --- | --- | --- |
| 重载插件与界面 | `hmr.reconcileProfile()` 重扫 profile 与 patch，逐出并重新 import 变了的模块；再发布 client bundle 新版本，然后刷新页面 | **不会** |
| 完全重启… | 宿主进程优雅退出（等于你手动关掉 DSH），有二次确认 | 会，要你自己再打开 |

两个实现上的坑，得记下来：

- **重载必须「先回话、后干活」。** `reconcileProfile()` 会把磁盘上变了的模块逐出 ——
  而这个插件自己的 `index.js` 几乎总是变过的那一个。如果在命令 handler 里 `await` 它，
  模块会在 handler 返回之前就被逐出，命令永远不回话、界面卡在「正在重载」。
  所以 handler 先写一条状态标记、把重载甩出去、立刻返回；页面刷新后再读回结果显示。
- **不自己 spawn 一个新的 `DeepSeek Harness.exe`。** 那会和当前实例抢单实例锁，
  结果是「旧窗口还在、新窗口一闪而过」。`app.relaunch()` 在 Electron 主进程里，
  插件碰不到，所以「完全重启」只做优雅退出这一步。

按钮只在桌面版出现（那行窗口菜单本来就是 Electron 预加载脚本挂的），
纯浏览器打开 Web GUI 时不会多一个和窗口对不上的按钮。

自检从 10 条加到 **11 条**：新断言同时盯住「重载被甩出 handler」和
「原有的 5 个注册一个都没少」。


### 1.6.3

**存储页多了「按产生日期」分组，让你能判断这批孤儿是什么时候来的。**

起因是个真问题：有人问"那些孤儿附件都是我删过的对话的产物吗"。答案是**没法证明**——
附件按 sha256 内容寻址，文件名就是哈希，DSH 不记录"这张图来自哪个对话"。

唯一能用的线索是**时间**。所以现在扫完会按日期列出：

```
按产生日期（帮你判断这批是什么时候来的）
  2026-10-25    1 个    0.0 MB
  2026-10-21   27 个   67.1 MB   ← 这一天的占了一大半，多半是同一次批量操作的产物
  2026-10-20    6 个   17.7 MB
  2026-09-30   16 个    2.6 MB
```

某一天占了总数一半以上时会额外标出来 —— 那通常是"某次批量粘贴"的特征，
比零散分布更容易回忆起来。

日期按**本地时区**切，不是 UTC —— 你想的是"10 月 21 日那天"，不是 UTC 的那天。

新增 2 条测试（`test/storage-scan.test.mjs` 现共 9 条）：按日期分组的个数与字节
必须与孤儿总数严格一致（防止界面上出现自相矛盾的数字）；没有孤儿时 `days` 是空数组。

### 1.6.2

**修一个会误删还能用的附件的 bug：孤儿扫描没把回收站里的会话算进去。**

`scanAttachments` 只扫 `$DSH_HOME/sessions/`，但 `$DSH_HOME/trash/<id>/session/`
里还躺着被删对话的日志 —— 那些对话是**可恢复**的。只扫 sessions 会把它们引用的附件
判成孤儿，用户一旦从回收站恢复那个对话，图片就没了。

**"已删除"和"可恢复的已删除"是两件事**，只有前者能让引用失效。

修复后在真实数据上的效果（同一台机器，修复前后对比）：

| | 修复前 | 修复后 |
| --- | --- | --- |
| 仍被引用 | 726 | **731** |
| 孤儿附件 | 55 | **50** |
| 孤儿占用 | 88.7 MB | **87.4 MB** |

多出来的 5 个就是回收站里那个会话引用的附件 —— 之前会被误删。

界面上「仍被引用」那行现在会显示 `+ N 个回收站日志`，让用户知道这个数是怎么来的。

新增两条测试（共 7 条）：回收站会话引用的附件不算孤儿；活会话与回收站会话的引用
要合并计算，不重复也不漏。

| --- | --- |
| 插件源码快照 | 改插件代码前的手动快照 |
| 插件升级前备份 | 升级其它插件（如 workbuddy）前的备份 |
| `AGENTS.md` 覆盖前自动备份 | 你点「恢复守则」时插件自动生成的 `AGENTS.md.<时间戳>.bak` |
| 手动备份 | 其它手动留的 |
| 来源未知（旧备份） | 没有 meta 的历史条目 |

**三条刻意的取舍**：

- **绝不根据目录名猜来源。** `...-steward-...` 看着像插件快照，但名字里没有任何工作区
  或时间语义保证。猜出来的来源比没有来源更糟 —— 它看上去像真的。所以没有 meta 的
  一律进「来源未知」，界面上提供「补说明」入口让你自己填。
- **「来源未知」不允许整组清理。** 那一堆恰恰是最需要逐个看一眼的，
  给个一键清掉的口子等于把风险最高的操作做得最省事。
- **按组清理也是移进回收站。** 备份本身就是回退手段，删备份是最不该鲁棒性差的操作。
  进了回收站还能捞回来。

顺带修了一个真 bug：`/chat-backup` 的子命令解析用的是**整行** trim，
于是 `meta <id>` 拼成 `"meta 20261025-..."` 永远不等于 `'meta'` ——
所有带参数的子命令都被当成未知动作。已改成取第一个词。

命令行：

```
/chat-backup list                    # 按来源分组列出
/chat-backup meta <id> --kind=... --label64=... --workspace64=... --reason64=...
/chat-backup trash <id...>           # 指定条目
/chat-backup trash --group=<origin>  # 按来源整组
```

### 1.5.0

**新增「存储」分页：插件开始管它自己的垃圾了。**

之前的清理功能（回收站、备份清空、孤儿文件夹）只管**插件自己产生的**东西。
真正占空间的三项——附件库、会话日志、备份——一直没有入口。这次补上第一项。

**能看到的**：附件库 `$DSH_HOME/attachments/v1/objects` 一共有多少文件、多大，
多少还被会话引用，多少已经没有任何会话再引用它。

**孤儿是怎么判定的**：DSH 的附件按 sha256 内容寻址存放，文件名就是哈希。
插件把每个会话日志（多帧 zstd，追加式）逐帧解压成文本，抓出其中的 64 位 hex，
与附件文件名求差集 —— 剩下的就是孤儿。

实测一台用了两个月的机器：775 个附件 / 335 MB，其中 **75 个 / 152 MB 没有任何会话再引用**。

**三个刻意的取舍**：

- **不自动扫描**。切到这一页不会自动开跑，因为一次扫描要解压全部会话日志
  （实测约 1.5 秒）。先看轻量信息，点「扫描孤儿附件」才做重活。
- **不直接删**。清理是把文件**移进回收站**，和删对话同一套逻辑，可以在「回收站」分页恢复。
  恢复按 `origin.json` 记下的原始绝对路径逐个搬回，不是靠文件名倒推。
- **如实说明判定的边界**。如果某个会话记录早已被删掉（删完对话又清空了回收站），
  它引用过的附件就会失去引用来源，从而被判成孤儿。这一点写在界面上，不在文档里藏着。

顺带修了一个真 bug：`/chat-trash list` 早先把「非 file 即 conversation」写死，
导致新加的附件批次条目在回收站里显示成对话。现在按 `file` / `attachments` / `conversation`
三类正确区分。

新增 `test/storage-scan.test.mjs`（5 条）：覆盖「被引用不算孤儿」「多帧必须逐帧解压」
「没有日志时全部算孤儿」「目录不存在不抛错」「半截坏帧不影响判定」——
第二条尤其重要，只读第一帧会把后面的引用全误判成孤儿。

命令行：`/chat-storage scan | clean | open`。

## 安装

把 `<profile>` 换成你的 profile 名（桌面端通常是 `desktop`，Web 端通常是 `web`）。

### 方式一：tarball（推荐，不依赖 git）

```sh
dsh plugin --profile <profile> add https://codeload.github.com/John4874314/dsh-steward/tar.gz/refs/tags/v1.7.6
```

不要求本机装 git，也不要求 `github.com:443` 可直连 —— 只走 `codeload.github.com`。

### 方式二：`github:` 简写

```sh
dsh plugin --profile <profile> add github:John4874314/dsh-steward
```

需要本机 `PATH` 里有 `git`，且能连上 `github.com:443`。在国内网络下
`github.com` 常常超时（`api.github.com` / `codeload.github.com` 却正常），
这时会报 `ERR_PNPM_GIT_RESOLVE_FAILED`，换方式一即可。

### 装完之后

**重启 DSH**。客户端 bundle 图在进程启动时构建，只按 `Ctrl/Cmd + Shift + R` 刷新页面
不会重新扫描新插件。

### 环境要求

- DSH **0.2.1-rc.1** 或更新（在 `0.2.1-rc.3` 上实测通过）
- Node ≥ 20
- Windows / macOS / Linux 均可装；其中解压、多浏览器选择、终端三项目前是 Windows 专用，
  见上面的「平台支持」。

### 装完先自检

不信任一个第三方插件是合理的。装完可以自己跑一遍它的自检：

```sh
git clone https://github.com/John4874314/dsh-steward && cd dsh-steward
npm test          # 9 条断言，不需要装任何依赖
```

或者只跑插件自带的只读体检：设置 → 对话管家 → 体检。它只读，不改任何文件。

## 功能

### 一、对话管理

#### 每个新对话一个文件夹（默认关闭）

设置 → 对话管家 → 对话管理 → 「每个新对话创建一个文件夹」。

- 默认在**发出第一条消息时**才建，空会话不留目录。
- 子代理不建（跟随父会话）；路径越界拒绝；非法字符替换成 `-`。
- 开关即时生效，配置存 `$DSH_HOME/chat-manager-config.json`。

#### 文件夹里自动写「交接日志.md」（默认开启）

设置 → 对话管家 → 对话管理 → 「在文件夹里写「交接日志.md」」。
这个开关只在「每个新对话创建一个文件夹」打开时才出现 —— 没有文件夹就没有落脚点。

每个对话自己的文件夹里会多出一份 `交接日志.md`，用途是**把任务交给别人（或几天后的自己）**：

| 段落 | 内容 |
| --- | --- |
| 概览 | 会话 id、标题、工作目录、创建时间、导出时间、消息数、省略了多少 |
| 产出的文件 | 这次对话里 `present` 过的交付物，一行一个绝对路径 + 说明 |
| 对话记录 | 按时间顺序：用户说了什么、助手回了什么、调了哪些工具（成功/失败） |

几个刻意的取舍：

- **什么时候写**：建目录时写一次；之后每个 `turn/end` 与 `session/end-seed` 各写一次，
  同会话 4 秒内只写一次（节流），避免长对话把磁盘写满。
- **怎么写的**：整份重新生成、写 `.tmp` 再 `rename` 原子覆盖 —— 不会留下半截文档。
- **为什么不是原样复制**：DSH 每轮都会把 `<system-reminder>`（内含 `AGENTS.md` 全文）
  拼进用户消息。实测一份 1.2 万条事件的对话里这类内容占 **48%**、同一份守则重复上千遍。
  日志会剔除这些注入块，只留人真正说过的话。
- **单条消息过长会截断**：默认每条上限 4000 字，保留头尾并标注省略了多少字；
  对话条数上限默认 400（超出的较早消息整段省略，页首写明）。
  完整原文始终在 `$DSH_HOME/sessions/` 里，日志只是"能读的摘要"。

想给一个**历史对话**补一份日志（早于本功能、或当时开关是关的）：

```
/chat-session-log --session=<会话 id> [--force] [--folder=<路径>]
```

#### 删除对话（可恢复）

对话行「⋯」菜单 → 「删除对话」。

确认框里可勾选「同时删除该对话的文件夹」。确认后：

1. 归档该对话
2. 发 `api-session/removed`，让侧边栏**立即**移除该行
3. 把会话记录目录**移进回收站**（不是删除）
4. 清理归档记录
5. 可选：把文件夹也移进回收站

> 内容进 `$DSH_HOME/trash/<id>/`，并写一条 `meta.json` 记下标题、时间、原路径。
> 设置页「回收站」里可以恢复或彻底删除。

#### 打开该对话的文件夹

对话行「⋯」菜单 → 「打开该对话的文件夹」，直接在资源管理器里定位。
没有登记过文件夹的对话**不显示这一行** —— 不占位，也不会出现点了没反应的按钮。

#### 批量删除

```
/chat-delete-batch --sessions=<id1,id2,...> [--with-folder]
```

逐个走同一条删除路径，全部进回收站，返回每个的成功/失败明细。

#### 文件右键菜单（按类型分组）

对话里的文件卡片、右侧「变更」审查行、右侧文件树，**点右键**（或用键盘 `Shift+F10` / 菜单键）都能弹出菜单。

菜单会先认文件类型，再决定放哪些动作。通用项永远在，专属项插在中间：

| 类型 | 识别方式 | 专属动作 |
| --- | --- | --- |
| **代码** | `.js .ts .py .go .rs .java .c .cpp .cs .php .sh .ps1 .sql .html .css .json .yaml …` | 复制代码、复制为 Markdown 代码块（带语言标注） |
| **文档** | `.md .txt .pdf .docx .xlsx .pptx .csv .epub …` | 复制文件内容 |
| **压缩包** | `.zip .7z .rar .tar .gz .tgz .bz2 .xz .zst …` | 解压到此处（同名目录已存在则拒绝，不覆盖） |
| **图片** | `.png .jpg .gif .webp .svg .bmp .ico .avif …` | 文件信息 |
| **音视频** | `.mp4 .mkv .mov .mp3 .wav .flac .m4a …` | 文件信息 |
| **可执行** | `.exe .msi .dll .so .dylib .bin .jar .wasm …` | 只给「文件信息」，**不提供任何运行入口** |
| **其它** | 其余扩展名 | 文件信息 |

通用项：

| 动作 | 说明 |
| --- | --- |
| 打开 / 打开文件夹 / 选择打开方式 | 走 `remote.session.*`，**不写会话日志** |
| 在终端中打开 | 在该文件所在目录起一个终端窗口 |
| 复制路径 | 复制绝对路径 |
| 复制为引用 | 复制成 `@<路径>`，粘贴到输入框即可定位 |
| 另存为… | 选目录后由宿主复制一份（同名自动加序号） |
| 重命名… | 同目录内改名，不覆盖已有文件 |
| 文件信息 | 大小 + 修改时间 |
| 移到回收站 | 文件进 `$DSH_HOME/trash/`，可恢复 |

外观是液态玻璃，颜色取 `--dsw-alias-*` 令牌，随深浅主题自动切换。菜单顶部的类型标签按类别着色（代码蓝、压缩包橙、可执行红），扫一眼就知道这是哪类文件。

> **为什么不给可执行文件「运行」**：右键菜单的路径来自对话内容，是模型可以影响的输入。
> 一个「运行」按钮等于给了一个静默执行任意程序的入口，收益远小于风险。

> 「打开 / 打开文件夹 / 打开方式 / 复制路径 / 复制为引用」不写日志；
> 「在终端中打开 / 另存为 / 重命名 / 移到回收站 / 解压 / 复制内容」必须由宿主执行，走 `/chat-file`，
> 会在对话里留一条命令记录 —— 这是浏览器无法直接写本地文件的必然代价。

#### 网址右键菜单

对话里的 **http/https 链接**上点右键，得到一套网址专用动作：

| 动作 | 说明 |
| --- | --- |
| 在默认浏览器打开 | 交给系统默认浏览器 |
| 用其它浏览器打开 | 列出本机已注册的浏览器（读 `StartMenuInternet`），逐个可选 |
| 复制网址 | 复制原始完整 URL |
| 复制为 Markdown 链接 | 复制成 `[链接文字](URL)` |

只接管 `http` / `https`。`javascript:`、`data:`、`file:` 一律放行给原生菜单，不进打开通道。

**带账号密码的链接**（`https://user:pass@host/`）不会被静默忽略 —— 那样右键毫无反应，像是坏了。
这类链接照常弹菜单，但：

- 顶部 URL 打码显示：`https://user:***@host/`，密码不露在屏幕上
- 多一行橙色警示：`⚠ 这个网址包含账号密码`
- 点「在浏览器打开」时**弹一次确认框**，说明凭据会被发给目标站点
- 复制类动作仍然可用，复制的是**完整原始 URL**（含真实密码）——复制到剪贴板是你主动的动作，不该被改写

安全靠「打开前确认」保证，不靠「什么都不给」。静默失败会让人以为插件坏了，
明确警示才会让人真的看一眼地址。

#### 图片右键菜单

对话里显示的图片（`.png` / `.jpg` / `.jpeg` / `.webp` / `.gif` / `.svg` / `.bmp` / `.avif`），
**点右键**就能：

| 动作 | 说明 |
| --- | --- |
| 打开图片 | 用系统默认看图程序打开 |
| 在文件夹中显示 | 在资源管理器里选中这个文件 |
| 另存为… | 选目录后复制一份（同名自动加序号） |
| 复制图片 | 图片直接进剪贴板，可以直接粘到聊天窗口 |
| 复制文件名 | 复制原始文件名（如 `image.png`） |

> 为什么需要绕一圈：界面里的图片是 `blob:` URL，浏览器不给你它的磁盘路径。
> 插件把图片字节算成 sha256，宿主按内容寻址到 `$DSH_HOME/attachments/v1/` 找回原图。
> DSH 的附件本来就按 sha256 存，哈希就是天然主键 —— 这样不必把 80KB 的图片
> base64 塞进命令（那会把会话日志刷成乱码）。

#### 正文里的文件路径也能右键

消息里出现的路径，右键就有「打开 / 在文件夹中显示 / 另存为 / 复制路径」：

```
E:\islet\docs\交接文档.md
@docs/PRD.md
./notes.md
~/Documents/a.pdf
```

- 相对路径（`@docs/PRD.md`、`./notes.md`）用**这个对话的工作目录**补全，
  所以拖进去的引用可以直接打开。
- 只认「指针真的落在那段文字上」的情况，而且必须是完整的一段带路径特征的文本。
  没有 `@` 的 `docs/PRD.md`、`https://…`、普通句子都不会触发 —— 宁可少弹，不要满屏乱弹。
- 想省事的话，拖选一段路径再右键也行（选中优先）。
- **对话里带文件图标的 `@引用` 小标签**（比如 `交接日志.md`）也能右键。那种标签的 DOM
  上只有文件名、没有路径，所以插件会把文件名交给宿主，在**这个对话的工作目录**里按名查找；
  同名文件有多个时会列出全部候选让你看清，不会猜一个打开。


### 二、运行守则（三原则）—— **默认关闭，要你自己开**

> **默认是关的。** 安装本插件**不会**改动你的 `$DSH_HOME/AGENTS.md`。
> 想用三原则，去 设置 → 对话管家 → 运行守则 → 「启用运行三原则」自己打开。
> 打开后才会往全局文件里写内容；关掉后不再注入，已写的那段留在文件里，需要你手动删。

打开后把三原则写进 **`$DSH_HOME/AGENTS.md`**（DSH 的全局指令文件），
**每个工作区、每个新会话**都会带上，harness 升级也不丢：

1. **不破坏 DSH 与系统** —— 不碰安装目录 / profile 配置 / 会话凭据 / 系统设置；不为完成任务降级安全。
2. **有风险的操作先验证** —— 说清「改什么 / 最坏怎样 / 怎么撤回」再执行；能小步试就不全量。
3. **留好备份、保证可回退** —— 改前备份、确认回退路径存在、改完验证、验证不过就回退。

正文见 [`AGENTS.guardrails.md`](./AGENTS.guardrails.md)。

> 本 bundle 的 patch 会**重新启用** `agent-instructions`（web-app bundle 默认禁用了它），
> 否则守则写进 `AGENTS.md` 也进不了上下文。副作用：项目里的 `AGENTS.md` / `CLAUDE.md`
> 也会被读进上下文。这一步与上面的开关无关 —— 它是 bundle 层的，装了就有。
> 如果你只想要对话文件夹/右键菜单、完全不想让 agent 读项目里的 `AGENTS.md`，
> 请删掉 `cordis.patch.yml` 里 `agent-instructions` 那一段再安装。

### 三、设置页的五个分页

| 分页 | 内容 |
| --- | --- |
| 对话 | 每个新对话一个文件夹、交接日志 两个开关 |
| 回收站 | 列表 / 恢复 / 彻底删除 / 清空，显示每条占用 |
| 备份 | 备份目录位置与占用，**一键清空** 或 **打开文件夹** 自行取舍 |
| 运行守则 | 三原则开关、全文展开、写入结果预览、用内置版本恢复 |
| 体检 | 一次只读自检，报告守则块 / 表单 / 配置 / 登记表 / 回收站 / 备份 |

#### 备份由你自己决定留还是删

写 `AGENTS.md` 等文件前会自动备份到 `$DSH_HOME/backups/`，备份会一直留着占磁盘。
「备份」分页因此给了两个按钮：**一键清空** 或 **打开备份文件夹** 自己挑。
插件不会替你自动删 —— 那是不可逆操作，该由你决定。

#### 备份约定：每条都要说清自己从哪来

这个目录不只插件在用：**你的 agent 改东西前留的快照也放这儿**。为了让这些备份在
一段时间后还看得懂，插件把下面这套约定写进了随它分发的守则正文
（`AGENTS.guardrails.md`）——你打开「运行三原则」后，它会随守则一起进
`$DSH_HOME/AGENTS.md`，于是 agent 每次改文件前都会照它做。

**位置**：`$DSH_HOME/backups/<YYYYMMDD-HHmmss>-<是什么>-<在改什么之前>/`

不要写死盘符 —— DSH 的 home 在不同机器上位置不同。放在这里的额外好处是：
它和 `sessions/`、`trash/` 同一个卷，移动是 `rename`，不复制字节。

**每条备份自带 `meta.json`**（目录备份放在目录里）：

```json
{
  "kind": "plugin-source",
  "label": "dsh-steward 源码快照",
  "source": "/绝对路径/到/被备份的东西",
  "workspace": "/触发这次备份的工作目录，无关就留空",
  "reason": "加备份来源分组之前",
  "createdAt": 1793542028019
}
```

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `kind` | 是 | `plugin-source` / `plugin-upgrade` / `guardrails` / `manual` |
| `label` | 是 | 一句话说清这是什么 |
| `source` | 是 | **被备份的东西原来在哪**（不是触发者） |
| `workspace` | 否 | 哪次工作流触发的；与被备份内容无关时**留空字符串** |
| `reason` | 是 | 为什么备份，用「<动作>之前」的句式 |
| `createdAt` | 是 | 毫秒时间戳 |

**两条硬规矩**：

1. **`source` 与 `workspace` 不许混用。** 备份的是 `$DSH_HOME/profiles/...` 下的插件，
   就不该把某个项目目录塞进 `source`；反过来，一次与工作区无关的备份，
   `workspace` 应当留空，而不是填一个「反正也对」的默认值 —— 那会让这个字段变成噪音。
2. **不确定就不写。** 宁可 `kind` 留 `manual`、`reason` 空着，
   也不要根据目录名猜一个看起来合理的来源。猜出来的来源比没有来源更糟，
   因为它看上去像真的。

「备份」分页会读这些元信息并按来源分组（插件源码快照 / 插件升级前 / 守则自动备份 /
手动 / 来源未知）。没有 `meta.json` 的历史备份显示为「来源未知」，不会被猜；
你可以直接在界面上给它**补说明**。「来源未知」那一组不提供整组清理 ——
那堆恰恰最需要逐个看一眼。

#### 体检报告什么

| 检查项 | 说明 |
| --- | --- |
| `guardrails` | 守则块在不在、标记是否配对、有没有残留旧标记 |
| `config-schema` | schemastery 是否可用（拿不到就没设置表单） |
| `config-file` | 配置文件能否读取、当前开关值 |
| `folder-registry` | 登记表里有多少条指向已不存在的目录 |
| `trash` | 回收站条目数与占用 |
| `backups` | 备份条目数与占用 |

全部只读，不改任何文件。

## 为什么不会拖垮 harness

这是本插件最看重的设计目标 —— **任何失败都只表现为「少一个功能」，绝不连累 DSH 本身**：

- **宿主半侧没有 Config 就降级**：schemastery 用运行时尝试获取（先本地、再 profile），
  拿不到就导出 `Config = undefined`，插件照常加载，只是没有设置表单。
- **守则写入整段包在 try/catch**，`apply` 结尾 `catch(() => {})`，任何失败都只是「没写进去」。
- **写 `AGENTS.md` 前先备份**到 `$DSH_HOME/backups/`，备份失败就放弃写入。
- **幂等**：靠 `<!-- dsh-steward:begin/end -->` 定位，只替换自己那段；
  还会顺手清理旧 guardrails 插件留下的 `guardrails:begin/end` 段。
- **客户端适配是弱引用**：对其它插件（如 `dsh-better-sidebar`）的集成一律用
  `ctx.get(...)` 探测 + try/catch，目标不存在就跳过，不影响本体。

已做故障注入：`DSH_HOME` 不存在、`config` 为 null、依赖缺失、重复 `apply` 均不抛错。

## 关于信任：这个插件会碰什么、不会碰什么

一个第三方插件要能删对话、能写文件，你当然该先问清楚它到底动什么。

**会写的文件**（全都在你明确开启对应开关之后）：

| 路径 | 什么时候 | 能不能反悔 |
| --- | --- | --- |
| `$DSH_HOME/chat-manager-config.json` | 你在设置页改开关 | 是，就是个 JSON |
| 对话文件夹 + 其中的 `交接日志.md` | 打开「每个新对话一个文件夹」后 | 是，删掉即可 |
| `$DSH_HOME/AGENTS.md` 里 `<!-- dsh-steward:begin/end -->` 之间 | 你手动打开「运行三原则」 | 是，关掉后手动删那一段 |
| `$DSH_HOME/backups/` | 每次改 `AGENTS.md` 前自动备份 | 是，设置页可一键清空 |
| `$DSH_HOME/trash/` | 删除对话 / 文件时**移动**进来 | 是，设置页可恢复 |

**明确不会做的**：

- **不联网，不上传任何东西**。宿主侧没有任何 `http` / `net` / `https` 调用。
  客户端有 2 处 `fetch`，只读本地 `blob:` / `data:` 地址（读界面里已经显示的那张图，
  用来算 sha256 和写剪贴板），不发往任何服务器。
- 不读 `$DSH_HOME/sessions/` 之外的数据；读会话只是为了生成交接日志，走 DSH 官方
  `sessionController.inspect()` 通道，不直接解析磁盘。
- 不改 DSH 安装目录、不改 `cordis.yml` / `cordis.patch.yml`、不改系统设置。
- 删除一律走回收站，不直接 `rm`；清空回收站需要你二次确认。

**已知的粗糙之处**（写在这里而不是藏起来）：

- 单文件插件，`index.js` 约 2,600 行、`client.js` 约 2,400 行，没有拆分模块。
- 测试只有 9 条契约断言，覆盖「名字一致 / 默认值 / 模块能加载 / icon 元信息」，
  **不覆盖 UI 交互**。
- Windows 优先开发，非 Windows 的三项功能是直接隐藏而非降级实现。
- npm 上只有源码包，没有编译产物；装完仍需重启 DSH 才生效。

## 配置

配置文件在 `$DSH_HOME/chat-manager-config.json`：

```json
{
  "folder": {
    "enabled": false,
    "trigger": "first-message",
    "template": "chat-{date}-{time}",
    "useAsWorkingDirectory": false
  },
  "guardrails": {
    "install": false
  },
  "sessionLog": {
    "enabled": true,
    "maxMessages": 400,
    "includeTools": true
  }
}
```

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `folder.enabled` | `false` | 是否每个新对话建一个文件夹 |
| `folder.trigger` | `first-message` | `first-message` 或 `session-start` |
| `folder.template` | `chat-{date}-{time}` | 支持 `{date}` `{time}` `{title}` `{id}` |
| `folder.useAsWorkingDirectory` | `false` | 建好后是否把该对话的工作目录切过去 |
| `guardrails.install` | **`false`** | 是否把三原则写进全局 `AGENTS.md`。默认关 |
| `sessionLog.enabled` | `true` | 是否在对话文件夹里写 `交接日志.md` |
| `sessionLog.maxMessages` | `400` | 最多导出多少条对话（0 = 不限，超出保留最近的） |
| `sessionLog.includeTools` | `true` | 日志里是否包含工具调用与结果 |

> 设置页暴露 `folder.enabled`、`sessionLog.enabled`、`guardrails.install` 三个开关；
> 其余字段需要手改这个 JSON。改完重启 DSH 生效。

## 卸载

设置 → 插件 → 已安装 → 移除。

`$DSH_HOME/AGENTS.md` 里的守则段**不会自动删除**（那是你的文件），
需要的话手删 `<!-- dsh-steward:begin -->` 与 `<!-- dsh-steward:end -->` 之间的内容。

> `node_modules/` 里指向 schemastery 的链接是设置表单用的，
> 删掉只会让设置页退化，不会让插件崩。
