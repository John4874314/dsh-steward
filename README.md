# dsh-steward —— 对话管家

插件在「已安装插件」里显示为 **`dsh-steward`**（包名 `@local/dsh-steward`），
设置页导航里显示中文「对话管家」。取名 `steward`（管家）是为了同时盖住它管的
两件事：对话本身（文件夹 / 删除 / 文件菜单）和运行守则（三原则基线）。

把原来两个插件合并成一个：

| 原插件 | 现在的能力 |
| --- | --- |
| `@local/chat-manager` | 每个对话一个文件夹、删除对话、文件右键菜单 |
| `@local/guardrails` | 运行三原则写进全局 `AGENTS.md` |

合并后只有**一个** bundle、一个开关、一个设置页。

## 一、对话管理

### 每个新对话一个文件夹（默认关闭）

设置 → 对话管家 → 对话管理 → 「每个新对话创建一个文件夹」。

- 默认在**发出第一条消息时**才建，空会话不留目录。
- 子代理不建（跟随父会话）；路径越界拒绝；非法字符替换成 `-`。
- 开关即时生效，设置存 `$DSH_HOME/chat-manager-config.json`（沿用旧文件名，升级不丢配置）。

### 文件夹里自动写「交接日志.md」（默认开启）

设置 → 对话管家 → 对话管理 → 「在文件夹里写「交接日志.md」」。
开关只在「每个新对话创建一个文件夹」打开时才出现 —— 没有文件夹就没有落脚点。

每个对话自己的文件夹里会多出一份 `交接日志.md`，用途是**把任务交给别人（或几天后的自己）**：

| 段落 | 内容 |
| --- | --- |
| 概览 | 会话 id、标题、工作目录、创建时间、导出时间、消息数、省略了多少 |
| 产出的文件 | 这次对话里 `present` 过的交付物，一行一个绝对路径 + 说明 |
| 对话记录 | 按时间顺序：用户说了什么、助手回了什么、调了哪些工具（成功/失败） |

几个刻意的取舍：

- **什么时候写**：建目录时写一次；之后每个 `turn/end` 与 `session/end-seed` 各写一次，
  同会话 4 秒内只写一次（节流），避免长对话把磁盘写满。
- **怎么写的**：整份重新生成、写 `.tmp` 再 `rename` 原子覆盖 —— 不会留下半截文档。
- **为什么不是原样复制**：DSH 每轮都会把 `<system-reminder>`（内含 `AGENTS.md` 全文）
  拼进用户消息。实测一份 1.2 万条事件的对话里这类内容占 **48%**、同一份守则重复上千遍。
  日志会剔除这些注入块，只留人真正说过的话。
- **单条消息过长会截断**：默认每条上限 4000 字，保留头尾并标注省略了多少字；
  对话条数上限默认 400（超出的较早消息整段省略，页首写明）。
  完整原文始终在 `$DSH_HOME/sessions/` 里，日志只是"能读的摘要"。

想给一个**历史对话**补一份日志（早于本功能、或当时开关是关的）：

```
/chat-session-log --session=<会话 id>
```

可选 `--force` 忽略开关、`--folder=<路径>` 指定目录。

### 删除对话

对话行「⋯」菜单 → 「删除对话」（原「归档」保留）。

确认框里可勾选「同时删除该对话的文件夹」。确认后：归档 → 发 `api-session/removed`
让侧边栏立即移除该行 → **把会话记录目录移进回收站** → 清理归档记录 → 可选把文件夹也移进回收站。

> 删除现在是**可恢复**的：内容进 `$DSH_HOME/trash/<id>/`，并写一条 `meta.json`
> 记下标题、时间、原路径。设置页「回收站」里可以恢复或彻底删除。

### 打开该对话的文件夹

对话行「⋯」菜单 → 「打开该对话的文件夹」，直接在资源管理器里定位。
没有登记过文件夹的对话不显示这一行（不占位、不出现点了没反应的按钮）。

### 批量删除

命令 `/chat-delete-batch --sessions=<id1,id2,...>`（可选 `--with-folder`）。
逐个走同一条删除路径，全部进回收站，返回每个的成功/失败明细。

### 文件右键菜单

对话里的文件卡片上**点右键**（或用键盘 `Shift+F10` / 菜单键）：

| 动作 | 说明 |
| --- | --- |
| 打开 / 打开文件夹 / 选择打开方式 | 走 `remote.session.*`，**不写会话日志** |
| 在终端中打开 | 在该文件所在目录起一个终端窗口 |
| 复制路径 | 复制绝对路径 |
| 复制为引用 | 复制成 `@<路径>`，粘贴到输入框即可定位 |
| 另存为… | 选目录后由宿主复制一份（同名自动加序号） |
| 重命名… | 同目录内改名，不覆盖已有文件 |
| 移到回收站 | 文件进 `$DSH_HOME/trash/`，可恢复 |

外观是液态玻璃，颜色取 `--dsw-alias-*` 令牌，随深浅主题自动切换。

> 「打开 / 打开文件夹 / 打开方式 / 复制路径 / 复制为引用」不写日志；
> 「在终端中打开 / 另存为 / 重命名 / 移到回收站」必须由宿主执行，走 `/chat-file`，
> 会在对话里留一条命令记录 —— 这是浏览器无法直接写本地文件的必然代价。

## 二、设置页的五个分页

| 分页 | 内容 |
| --- | --- |
| 对话 | 每个新对话一个文件夹、交接日志 两个开关 |
| 回收站 | 列表 / 恢复 / 彻底删除 / 清空，显示每条占用 |
| 备份 | 备份目录位置与占用，**一键清空** 或 **打开文件夹** 自行取舍 |
| 运行守则 | 三原则开关、全文展开、写入结果预览、用内置版本恢复 |
| 体检 | 一次只读自检，报告守则块 / 表单 / 配置 / 登记表 / 回收站 / 备份 |

### 备份由你自己决定留还是删

写 `AGENTS.md` 等文件前会自动备份到 `$DSH_HOME/backups/`，备份会一直留着占磁盘。
「备份」分页因此给了两个按钮：**一键清空** 或 **打开备份文件夹** 自己挑。
插件不会替你自动删——那是不可逆操作，按守则原则二该由你决定。

### 体检报告什么

| 检查项 | 说明 |
| --- | --- |
| `guardrails` | 守则块在不在、标记是否配对、有没有残留旧标记 |
| `config-schema` | schemastery 是否可用（拿不到就没设置表单） |
| `config-file` | 配置文件能否读取、当前开关值 |
| `folder-registry` | 登记表里有多少条指向已不存在的目录 |
| `trash` | 回收站条目数与占用 |
| `backups` | 备份条目数与占用 |

全部只读，不改任何文件。

## 二、运行守则（三原则）—— **默认关闭，要你自己开**

> **默认是关的。** 安装本插件**不会**改动你的 `$DSH_HOME/AGENTS.md`。
> 想用三原则，去 设置 → 对话管家 → 运行守则 → 「启用运行三原则」自己打开。

打开后把三原则写进 **`$DSH_HOME/AGENTS.md`**（DSH 的全局指令文件），
**每个工作区、每个新会话**都会带上，harness 升级也不丢：

1. 不破坏 DSH 与系统 —— 不碰安装目录/profile 配置/会话凭据/系统设置；不为完成任务降级安全。
2. 有风险的操作先验证 —— 说清「改什么 / 最坏怎样 / 怎么撤回」再执行；能小步试就不全量。
3. 留好备份、保证可回退 —— 改前备份、确认回退路径存在、改完验证、验证不过就回退。

正文见 [`AGENTS.guardrails.md`](AGENTS.guardrails.md)。

> 这个 bundle 的 patch 会**重新启用** `agent-instructions`（web-app bundle 默认禁用了它），
> 否则守则写进 AGENTS.md 也进不了上下文。副作用：项目里的 `AGENTS.md` / `CLAUDE.md`
> 也会被读进上下文。这一步与上面的开关无关 —— 它是 bundle 层的，装了就有。
> 完全不想让 agent 读项目 `AGENTS.md` 的话，删掉 `cordis.patch.yml` 里
> `agent-instructions` 那一段再装。

## 为什么不会拖垮 harness

- 宿主半侧**没有 Config 就降级**：schemastery 用运行时尝试获取（先本地、再 profile），
  拿不到就导出 `Config = undefined`，插件照常加载，只是没有设置表单。
- 守则写入整段包在 try/catch，`apply` 结尾 `catch(() => {})`，任何失败都只是"没写进去"。
- 写 `AGENTS.md` 前先备份到 `$DSH_HOME/backups/`，备份失败就放弃写入。
- 幂等：靠 `<!-- dsh-steward:begin/end -->` 定位，只替换自己那段；
  还会顺手清理旧 guardrails 插件留下的 `guardrails:begin/end` 段。

已做故障注入：`DSH_HOME` 不存在、`config` 为 null、依赖缺失、重复 apply 均不抛错。

## 卸载

设置 → 插件 → 已安装 → 移除。
`$DSH_HOME/AGENTS.md` 里的守则段不会自动删除（那是用户文件），需要的话手删标记之间的内容。

> 注意：`node_modules/` 里指向 schemastery 的链接是设置表单用的，删掉只会让设置页退化，不会让插件崩。
